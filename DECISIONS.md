# Решения

- **Только Android.** Так сказал владелец проекта. Electron/.exe в этой итерации не собирается, а клиент остаётся веб-кодом, чтобы ПК-обёртку можно было добавить позже.
- **Без Capacitor/Gradle.** `dl.google.com` (Google Maven и Android SDK) закрыт сетевой политикой окружения, поэтому AGP и Capacitor не собираются. Вместо них используется Android SDK из пакетов Ubuntu (`android-sdk`, `android-sdk-platform-23`, `dalvik-exchange`) и собственная Java-оболочка с WebView, которая повторяет то, что дал бы Capacitor (раздача ассетов с https-origin, JS-мост).
- **compileSdk 23, targetSdk 33, minSdk 24.** Из доступных офлайн платформ есть только android.jar API 23. Более новые API вызываются через рефлексию. Значение targetSdk 33 позволяет устанавливать APK на Android 14+ без предупреждений о старом приложении.
- **Собственный WebGL2-рендерер вместо PixiJS.** Мир рисуется одной текстурой (1 пиксель = 1 клетка) с шейдером затенения, освещения и слоёв, а существа рисуются инстансингом. Это быстрее и проще, чем 1M спрайтов-тайлов в Pixi.
- **Процедурные ассеты.** kenney.nl, opengameart.org, freesound и другие сайты закрыты сетевой политикой. Спрайты, тайлы, иконки и звуки генерируются кодом, а загрузчик подхватывает файлы из `/assets` по именам, если их положить.
- **Тик 12 Гц.** Это середина диапазона 10–20: достаточно для плавной интерполяции и экономно на телефоне.
- **ГПСЧ sfc32.** Быстрый, 128 бит состояния, легко сериализуется.
- **Без SharedArrayBuffer.** WebView без cross-origin isolation его не даёт, поэтому всегда используются передаваемые ArrayBuffer (двойной буфер).
- **Вещества и огонь — на уровне клеток, без частиц.** Это дёшево и детерминированно.
- **Ключ подписи** лежит в `tools/signing/debug.keystore` (пароль `android`). Он отладочный и общий для всех этапов. Релизный ключ этапа 12 создаётся отдельно (`tools/signing/release.keystore`) и в реальном проекте должен храниться вне репозитория.
- **AAB на этапе 12.** Нужен bundletool, которого нет в Maven Central. Решение принимается на этапе 12.
- **База бенчмарка обновляется на каждом этапе.** Если этап намеренно добавляет системы, после оптимизации база пересчитывается (`pnpm bench -- --update`). Дальнейшие изменения внутри этапа сравниваются с ней, допуск 15 %. Абсолютный бюджет тика (8 мс) проверяется всегда.

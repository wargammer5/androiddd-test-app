# Сотворение — архитектура

Песочница «симулятор бога»: вид сверху, пиксельный мир, существа, города, королевства, религии, войны и божественные силы.
Целевая платформа этой итерации — **Android** (APK). Код клиента платформенно-независим (браузер + WebView), ПК-обёртка оставлена на следующую итерацию (см. DECISIONS.md).

## Стек

| Слой | Технология |
|---|---|
| Язык | TypeScript 5, `strict` |
| Монорепозиторий | pnpm workspaces |
| Сборка клиента | Vite (ES2022, module worker) |
| Симуляция | чистый TS без DOM, Web Worker в игре, Node в тестах/бенчмарках |
| Рендер | собственный WebGL2-рендерер: мир как текстура 1 px = 1 клетка с подгрузкой изменённых чанков, существа/объекты — инстансинг квадов из атласа, фильтрация `NEAREST` |
| Интерфейс | Preact поверх canvas, адаптивная вёрстка |
| Данные | JSON в `packages/content/data`, валидация zod |
| Сохранения | двоичный формат с версией, сжатие fflate, чанки-секции, миграции |
| Звук | Web Audio API, процедурный синтез (без внешних файлов), загрузчик `.ogg` по именам из `/assets/sfx` |
| Android | нативная оболочка на Java: `Activity` + `WebView`, ассеты отдаются с `https://appassets.androidplatform.net/` через `shouldInterceptRequest`, JS-мост `SotvAndroid` (файлы, шаринг, вибрация, «назад», жизненный цикл). Сборка APK — `tools/android/build-apk.mjs` (aapt2 → javac → dx → zipalign → apksigner) |
| Тесты | Vitest (ядро), Playwright + Chromium (смоук клиента в мобильном вьюпорте) |

## Структура

```
packages/sim       ядро: rng, мир, генерация, вещества, ECS, пути, ИИ, природа, города, королевства,
                   дипломатия, культура/язык/религия, силы, события, сохранения
packages/content   JSON-данные и zod-схемы, валидатор
packages/client    worker, рендер, камера, ввод, UI (Preact), звук, платформенный слой, i18n
apps/android       Java-оболочка, манифест, ресурсы
tools              сборка APK, проверка артефактов, бенчмарк, генерация CREDITS, ключ подписи
dist/stage-N       готовые APK и CHANGELOG по этапам
```

## Ключевые решения ядра

- **Детерминизм**: всё случайное — `Rng` (sfc32) из сида мира; состояние ГПСЧ сохраняется. Порядок обхода фиксирован. Тест: два прогона одного сида дают одинаковый хеш состояния.
- **Время**: фиксированный тик 12 Гц, скорости 0/1/2/4/8× (кратное число тиков за интервал, ограничение по бюджету времени), рендер интерполирует позиции существ.
- **Мир**: слои в типизированных массивах `W*H`; чанки 32×32 с флагами `dirty` (для рендера/сохранения) и `active` (для веществ и огня).
- **Сущности**: SoA, ёмкость предвыделена, ID = index | generation<<20, пространственный хеш 16×16.
- **Пути**: A* по сетке с ограничением узлов + кэшируемые flow field для массовых целей; анти-застревание (тайм-аут прогресса → пересчёт, смена цели, телепорт на ближайшую проходимую).
- **ИИ**: Utility AI с потребностями (голод, сон, отдых, общение, безопасность), чертами и настроением; порционное обновление `id % N`; простоя нет — при отсутствии цели всегда находится действие (бродить, собирать, работать).
- **Связь с клиентом**: worker шлёт кадр: позиции существ (Float32Array, transferable, двойной буфер), список изменённых чанков (RGBA-патчи), события, статистику. Команды игрока идут в worker очередью и применяются в начале тика (детерминированно).

## Бюджеты

| Метрика | Цель |
|---|---|
| Android средний класс | 30–60 fps, 800 существ |
| Тик симуляции 1× | ≤ 8 мс |
| Память Android | ≤ 400 МБ |
| Холодный старт | ≤ 3 с |
| APK | ≤ 150 МБ |
| Регрессия бенчмарка | ≤ 15 % от `tools/bench/baseline.json` |

## Критерии приёмки этапа

1. `pnpm test` зелёный (юнит + детерминизм + сохранения).
2. `pnpm build:web` без ошибок типов; Playwright-смоук доходит до главного экрана и мира без ошибок консоли.
3. `pnpm build:apk` даёт `Sotvorenie-v{версия}-stage{N}.apk`; `apksigner verify` и `aapt dump badging` проходят, размер в бюджете.
4. Бенчмарк не хуже базы более чем на 15 %.
5. APK и CHANGELOG скопированы в `dist/stage-N/`, PROGRESS.md обновлён, коммит с тегом `stage-N`.
